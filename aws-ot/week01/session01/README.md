# Session 01 - Why AWS for everyone

## Outcomes

- 클라우드가 "인프라"가 아니라 "제품 개발 속도와 리스크"의 문제라는 것을 이해한다.
- Shared responsibility model을 설명하고, 보안 논의를 어디에서 해야 하는지 정리한다.
- AWS 글로벌 인프라 용어(Region, AZ)로 가용성 설계를 말할 수 있다.

## Why This Matters (by role)

- Developer: 인프라 요청 리드타임이 줄어 기능 실험이 빨라지고, 표준 서비스를 통해 보안과 운영 부담이 감소한다.
- PM or Planner: 비용 구조와 리드타임을 이해하면 기능 우선순위와 런칭 리스크를 더 정확히 조정할 수 있다.
- On-prem Ops: 운영의 초점이 "장비 관리"에서 "정책, 가시성, 자동화"로 바뀌며, 표준 패턴으로 장애 대응이 단순해진다.

## Timebox (4h)

- Theory: 2h 30m
- Demo or Workshop (console-first): 1h
- Quiz and Review: 30m
