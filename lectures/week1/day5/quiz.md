# 퀴즈 (Quiz)

## 질문 1

**호스트(내 PC)에서 컨테이너의 웹 서비스에 접근하기 위해 가장 일반적으로 필요한 설정은 무엇인가?**

A) 컨테이너에 `--restart=always`를 설정한다  
B) `docker run`에서 `-p HOST_PORT:CONTAINER_PORT`로 포트를 퍼블리시한다  
C) 컨테이너 이름을 `web`로 지정한다  
D) `docker network connect`만 수행하면 자동으로 호스트에서 접근 가능해진다  

<details>
<summary>정답 및 해설 보기</summary>

**답**: B

**설명**: 컨테이너 내부 포트가 열려 있어도 호스트로 자동 노출되지는 않습니다. 호스트에서 접근하려면 `-p 8080:80`처럼 호스트 포트와 컨테이너 포트를 매핑해야 합니다. 이때 혼동하기 쉬운 점은 "컨테이너 포트 80"과 "호스트 포트 8080"이 다르며, 실제 접속은 호스트 포트를 사용한다는 것입니다.

</details>

## 질문 2

**유저 정의 브리지 네트워크(user-defined bridge)를 사용하는 주요 이점으로 가장 적절한 것은 무엇인가?**

A) 컨테이너가 자동으로 호스트 방화벽을 우회한다  
B) 컨테이너 이름 기반 DNS로 서비스 간 통신이 쉬워진다  
C) 컨테이너 이미지 크기가 줄어든다  
D) 컨테이너 로그가 자동으로 중앙 수집된다  

<details>
<summary>정답 및 해설 보기</summary>

**답**: B

**설명**: 유저 정의 브리지 네트워크에서는 컨테이너 이름을 DNS로 해석해 `http://web`처럼 통신하기가 쉬워집니다. IP를 하드코딩하지 않아도 되고, 컨테이너를 재생성해 IP가 바뀌어도 이름 기반으로 연결할 수 있어 개발/테스트에서 매우 유용합니다.

</details>

## 질문 3

**컨테이너 내부에서 `localhost`가 의미하는 대상으로 올바른 것은 무엇인가?**

A) 항상 Docker 호스트(내 PC)를 가리킨다  
B) 항상 같은 네트워크의 다른 컨테이너를 가리킨다  
C) 해당 컨테이너 자기 자신을 가리킨다  
D) Docker 레지스트리를 가리킨다  

<details>
<summary>정답 및 해설 보기</summary>

**답**: C

**설명**: 컨테이너는 격리된 네트워크 네임스페이스를 가지므로 컨테이너 내부의 `localhost`는 "그 컨테이너 자신"입니다. 다른 컨테이너에 접근하려면 같은 네트워크에 있어야 하고, 보통 컨테이너 이름(DNS)이나 IP를 사용합니다. 이 혼동이 네트워크 트러블슈팅에서 가장 빈번합니다.

</details>

## 질문 4

**`client` 컨테이너에서 `http://web`로 접근하려면 일반적으로 어떤 조건이 필요하나?**

A) `client`와 `web`이 같은 Docker 네트워크에 연결되어 있어야 한다  
B) `web`이 반드시 `--privileged`로 실행되어야 한다  
C) `web`은 반드시 `-p`로 호스트에 퍼블리시되어야 한다  
D) `client`는 반드시 호스트 네트워크 모드(`--network host`)여야 한다  

<details>
<summary>정답 및 해설 보기</summary>

**답**: A

**설명**: 컨테이너 간 통신은 같은 네트워크에 붙어 있어야 가능합니다. 호스트 퍼블리시(`-p`)는 "호스트에서 접근"할 때 필요하고, 컨테이너끼리 통신할 때는 같은 네트워크 + 서비스 이름(DNS) 조합이 핵심입니다. 즉 `web`을 호스트에 열지 않아도 같은 네트워크면 `client -> web` 통신이 가능합니다.

</details>

## 질문 5

**`docker network connect` 명령의 용도로 가장 올바른 설명은 무엇인가?**

A) 이미지를 레지스트리에 업로드한다  
B) 실행 중인 컨테이너를 추가 네트워크에 연결한다  
C) 컨테이너 포트를 호스트로 퍼블리시한다  
D) 컨테이너 내부 프로세스를 재시작한다  

<details>
<summary>정답 및 해설 보기</summary>

**답**: B

**설명**: 컨테이너는 생성 시 하나 이상의 네트워크에 연결될 수 있고, 실행 중에도 `docker network connect`로 추가 네트워크에 연결할 수 있습니다. 이를 통해 네트워크 격리를 유지하면서도 필요한 통신만 점진적으로 허용할 수 있습니다. 반대로 너무 많은 네트워크를 붙이면 보안/복잡도가 증가하므로 최소 연결 원칙을 권장합니다.

</details>
