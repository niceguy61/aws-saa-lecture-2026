# 2주차 - Docker와 Docker Compose

## 목표

컨테이너를 추상 개념이 아니라 애플리케이션을 같은 방식으로 실행하기 위한 도구로 이해한다.

## 2주차 운영 기준

2주차부터는 1주차보다 강의 깊이와 실습 밀도를 높인다. 대상 수준은 대학교 이공계 전공자 또는 주니어 엔지니어 초입으로 잡고, Docker를 "명령어 몇 개"가 아니라 애플리케이션 실행 환경을 표준화하는 운영 기술로 다룬다.

- 각 Day 자료는 1주차보다 더 긴 설명, 비교표, 실패 사례, 검증 절차를 포함한다.
- 모든 핸즈온은 prerequisites, commands, expected output, verification, troubleshooting, cleanup을 갖춘다.
- Docker의 등장 배경, VM과의 관계, 이미지 배포 문화, OCI/containerd 흐름처럼 업계 변천사를 함께 읽는다.
- 학생들이 지치지 않도록 실제 팀에서 겪는 "내 노트북에서는 되는데요", 빌드 캐시 사고, 포트 충돌, 이미지 태그 혼동 같은 이야기를 실습과 연결한다.

| 일차 | 주제 | 활동 |
|---|---|---|
| [1일차](day01/README.md) | 컨테이너 개념 모델 | 간단한 컨테이너를 실행하고 상태, 로그, 내부 접근, 중지, 삭제를 안전하게 연습한다. |
| [2일차](day02/README.md) | Docker Image | 간단한 API 이미지를 빌드하고 tag를 붙인 뒤 실행한다. Dockerfile의 각 줄이 어떤 역할을 했는지 설명한다. |
| [3일차](day03/README.md) | 런타임 설정 | 시작은 되지만 제대로 동작하지 않는 컨테이너를 로그, 포트 매핑, 환경 변수를 근거로 고친다. |
| [4일차](day04/README.md) | Docker Compose | Docker Compose로 API와 데이터베이스를 실행하고, API가 DB에 도달하는 방식을 증명한다. |

## 주차 산출물

- Docker 개념도
- Dockerfile 체크리스트
- Compose 네트워크 다이어그램
- 스틱맨 이미지: 서로 다른 노트북에서 같은 앱을 실행하려는 팀
