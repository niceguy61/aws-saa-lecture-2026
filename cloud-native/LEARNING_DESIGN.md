# 학습 설계 가이드

이 과정은 Cloud Native 시스템을 처음 배우는 비전공 대학생을 기준으로 설계합니다.
강의는 천천히, 시각적으로, 실습 가능하게, 안전하게 진행합니다.

## 기본 수업 루프

VAKOG 대신 다음 흐름을 사용합니다.

1. 보기: 시스템의 모양, 흐름, 문제를 먼저 보여준다.
2. 설명하기: 개념 이름과 mental model을 붙인다.
3. 해보기: 작은 명령, 랩, 활동을 직접 해본다.
4. 진단하기: 일부러 깨뜨리거나 관찰하고 증상에서 원인을 추론한다.
5. 회고하기: 운영 판단과 tradeoff를 한 문장으로 정리한다.

모든 교시에 다섯 단계를 넣을 필요는 없습니다. 다만 하루 전체에는 다섯 요소가 모두 들어가도록 설계합니다.

## 학습자 기준

학습자는 다음 상태라고 가정합니다.

- 브라우저와 기본 파일 조작은 할 수 있다.
- 터미널 경험은 적을 수 있다.
- 네트워크, Linux, 프로세스, 포트, HTTP를 깊게 알지 못할 수 있다.
- 아키텍처보다 용어와 그림이 먼저 필요하다.
- 구체적인 애플리케이션에 연결될 때 개념을 더 잘 이해한다.

## 난이도 레이어

자료는 세 단계로 나눕니다.

- Core: 모두가 반드시 따라와야 하는 내용
- 보충: 배경지식이 부족한 학생을 위한 짧은 보충 자료
- 심화: 빠르게 이해한 학생이나 복습용 심화 자료

## 하루 수업 리듬

수업은 09:00부터 18:00까지 진행합니다.
50분 수업, 10분 휴식을 기본으로 합니다.
점심은 13:00에 시작합니다.

기본 하루 흐름:

- 1-2교시: 개념 이야기와 mental model
- 3-4교시: 강사 데모 또는 구조화된 설명
- 5-6교시: 랩, 미션, 애플리케이션 시연
- 7교시: 문제 해결, 비교, 선택형 심화
- 8교시: 정리, 퀴즈, 회고, 다음 수업 연결

## Hands-On 원칙

대부분의 날은 1-2시간 정도의 hands-on을 포함합니다.
다만 이론 설명이 먼저 필요한 날에는 hands-on을 강제로 넣지 않습니다.
그 경우 다음 중 하나로 대체합니다.

- 강사가 직접 만든 데모 애플리케이션
- 짧은 영상 분석
- 아키텍처 walkthrough
- 디버깅 theater
- 설계 미션
- 구체적인 의사결정을 다루는 팀 토론

## 미션 설계

중간중간 짧고 재미있는 미션을 넣어 피로도를 낮춥니다.

좋은 미션 예시:

- 고장난 컨테이너 구출하기
- 빠진 환경 변수 찾기
- 데이터베이스에 연결하지 못하는 앱 살리기
- 브라우저에서 Pod까지 트래픽 경로 그리기
- 가장 안전하고 저렴한 AWS 배포 경로 고르기
- 로그, 메트릭, 트레이스로 장애 설명하기

미션은 20-50분 안에 끝낼 수 있어야 하고, 결과가 명확해야 합니다.
