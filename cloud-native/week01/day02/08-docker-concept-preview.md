# 8교시 - Day2 핵심 정리와 Docker 개념 Live QA

## 목표

이 시간의 목표는 Day2에서 배운 프로세스, 포트, 파일, 환경 변수, 로그를 다시 정리하고, 이 개념들이 Docker로 어떻게 이어지는지 확인하는 것이다. 남은 시간은 실습 오류와 Docker 개념 질문을 Live QA로 해결한다.

이 세션의 끝에서 우리는 다음을 말할 수 있어야 한다.

- 프로그램과 프로세스의 차이를 설명한다.
- 포트와 localhost가 요청 흐름에서 어떤 역할인지 말한다.
- 파일, 환경 변수, 로그가 운영에서 왜 중요한지 설명한다.
- Docker가 실행 환경 차이를 줄이기 위해 등장했다는 점을 이해한다.

## 오늘 한 줄 요약

Day2는 작은 웹앱을 통해 “앱이 실행된다”는 말 안에 프로세스, 포트, 요청, 설정, 로그가 들어 있음을 확인한 날이다.

## 반드시 알아야 할 키포인트

- 프로세스는 실행 중인 프로그램이다.
- 서버는 특정 포트에서 요청을 기다린다.
- `localhost`는 내 컴퓨터 자신을 뜻한다.
- 환경 변수는 실행할 때 바꿀 수 있는 설정값이다.
- 로그는 앱이 무엇을 했는지 남기는 증거다.
- 브라우저 화면보다 서버 로그가 더 정확한 단서일 때가 많다.
- 앱이 안 열릴 때는 주소, 포트, 서버 실행 상태, 로그 순서로 확인한다.

## Docker 개념으로 연결

오늘 만든 작은 웹앱을 친구 컴퓨터에서도 똑같이 실행하려면 여러 조건이 맞아야 한다.

- Python이 설치되어 있어야 한다.
- `server.py` 파일이 있어야 한다.
- 실행 명령을 알아야 한다.
- 포트를 알아야 한다.
- 필요한 환경 변수를 맞춰야 한다.
- 로그를 볼 수 있어야 한다.

Docker는 이 실행 조건을 이미지로 포장하고, 컨테이너라는 실행 단위로 반복하려는 도구다.

| Day2 개념 | Docker에서 다시 만나는 질문 |
|---|---|
| 파일 | 이미지 안에 어떤 파일이 들어갔는가? |
| 프로세스 | 컨테이너가 어떤 명령으로 시작되는가? |
| 포트 | 어떤 포트를 열고 있는가? |
| 환경 변수 | 실행할 때 어떤 값을 바꿀 수 있는가? |
| 로그 | 문제가 생기면 무엇을 봐야 하는가? |

## VM과 컨테이너 맛보기

| 구분 | VM | 컨테이너 |
|---|---|---|
| 비유 | 컴퓨터 한 대를 통째로 빌리는 느낌 | 앱 실행 방을 가볍게 나누는 느낌 |
| OS 구조 | 각 VM이 게스트 OS를 가짐 | 보통 호스트 OS 커널을 공유 |
| 시작 속도 | 상대적으로 느림 | 상대적으로 빠름 |
| 주의 | 무겁고 느릴 수 있음 | 권한과 보안 설정이 중요 |

정확한 내부 구조는 2주차에 더 다룬다. 지금은 “컨테이너 안에서도 결국 프로세스가 실행되고, 포트를 열고, 로그를 남긴다”는 점을 기억한다.

## Live QA

남은 시간은 Day2 실습과 Docker 연결 질문을 해결한다.

우선순위:

1. Python 실행 문제
2. `localhost:8000` 접속 문제
3. 포트 충돌 또는 서버 중지 문제
4. 로그가 안 보이거나 의미를 모르겠는 문제
5. Docker 이미지/컨테이너 개념 질문

질문 예시:

```text
제가 하려던 일: Day2 웹앱 실행
보인 증상: localhost:8000 접속 실패
이미 해본 것: python3 server.py 실행, 브라우저 새로고침
궁금한 것: 서버가 꺼진 것인지 포트가 틀린 것인지 확인하고 싶음
```
