# 6교시 - 미션: 깨진 명령어 고치기

## 목표

이 시간의 목표는 실패하는 명령어를 보고 원인을 찾고, 올바른 명령으로 고치는 것이다. 실무에서 대부분의 시간은 “처음부터 맞는 명령을 치는 일”보다 “틀린 명령의 원인을 좁히는 일”에 가깝다.

이 세션의 끝에서 우리는 다음을 할 수 있어야 한다.

- 에러 메시지에서 원인 후보를 찾는다.
- 현재 위치, 파일 이름, 옵션, 대소문자 문제를 확인한다.
- 고친 명령과 근거를 함께 설명한다.

## 오늘 한 줄 요약

깨진 명령을 고치는 힘은 명령 암기가 아니라, 현재 위치와 에러 메시지를 읽는 힘에서 나온다.

## 미션 규칙

각 문제마다 아래 네 줄을 채운다.

```text
원래 명령:
보인 에러:
고친 명령:
근거:
```

중요한 규칙:

- 에러 메시지를 복사하거나 핵심 단어를 적는다.
- `pwd`와 `ls`로 현재 위치를 확인한다.
- 같은 명령을 무작정 반복하지 않는다.
- AI에게 물어본다면 에러 메시지와 현재 위치를 같이 준다.

## 준비

저장소 루트에서 시작한다.

```bash
cd cloud-native/week01/day03/playground
```

현재 위치:

```bash
pwd
```

## 깨진 명령 8개

아래 명령은 일부러 틀렸다. 바로 답을 보지 말고, 실행해서 에러를 읽고 고친다.

### 1번

```bash
ls log
```

힌트: 폴더 이름을 확인한다.

### 2번

```bash
cat logs/access
```

힌트: 파일 확장자를 확인한다.

### 3번

```bash
grep ERROR log/error.log
```

힌트: 경로의 어느 부분이 틀렸는가?

### 4번

```bash
tail -5 logs/access.log
```

힌트: 일부 환경에서는 동작할 수 있지만, 더 명확한 표준 형태로 고쳐본다.

### 5번

```bash
cat config/App.env
```

힌트: Linux 계열 파일 시스템에서는 대소문자가 중요하다.

### 6번

```bash
grep DATABASE logs/access.log
```

힌트: 찾는 단어가 어느 파일에 있을 가능성이 높은가?

### 7번

```bash
cd apps/backend
```

힌트: 실제 앱 폴더 이름을 확인한다.

### 8번

```bash
python server.py
```

힌트: 오늘 `playground`에는 실행할 `server.py`가 없다. 이 명령은 어떤 잘못된 전제를 가지고 있는가?

## 예상 원인 분류

| 원인 | 예시 |
|---|---|
| 오타 | `log` vs `logs` |
| 파일명 누락 | `access` vs `access.log` |
| 대소문자 | `App.env` vs `app.env` |
| 현재 위치 착각 | 다른 폴더에서 실행 |
| 잘못된 전제 | 없는 파일 실행 |
| 검색 대상 오류 | 단어가 다른 파일에 있음 |

## 제출 형식

팀별로 가장 어려웠던 2개를 골라 아래 형식으로 정리한다.

```text
문제 번호:
원래 명령:
에러 핵심:
고친 명령:
왜 이렇게 고쳤는가:
다음부터 먼저 확인할 것:
```

## 도전 과제

아래 명령의 의미를 설명한다.

```bash
grep "status=500" logs/access.log && grep "DATABASE_URL" logs/error.log
```

`&&`는 앞 명령이 성공했을 때만 뒤 명령을 실행한다. CI/CD와 배포 스크립트에서 이런 연결이 자주 등장한다.
