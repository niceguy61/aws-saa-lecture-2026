# 8교시 - Day3 핵심 정리와 Live QA

## 목표

이 시간의 목표는 Day3에서 배운 터미널 생존법을 다시 정리하고, 오후 미션에서 막힌 명령과 에러 해석을 Live QA로 해결하는 것이다. 오늘 배운 명령은 Docker, Kubernetes, AWS에서도 계속 반복된다.

이 세션의 끝에서 우리는 다음을 할 수 있어야 한다.

- 터미널에서 길을 잃었을 때 복구 순서를 말한다.
- 로그와 설정 파일을 연결해 원인 후보를 설명한다.
- 위험한 삭제 명령을 구분하고 멈출 수 있다.
- 에러를 질문 템플릿으로 바꿔 도움을 요청한다.

## 반드시 알아야 할 키포인트

- 길을 잃으면 `pwd`와 `ls`부터 본다.
- 파일이 없다는 에러는 현재 위치, 폴더 이름, 파일명, 대소문자를 의심한다.
- `grep` 결과가 없다는 것은 조건에 맞는 줄을 못 찾았다는 뜻일 수 있다.
- `404`는 요청 경로를 못 찾은 것이고, `500`은 서버 처리 중 실패한 것이다.
- 에러 메시지는 숨길 것이 아니라 원인을 찾는 증거다.
- `rm`, `rm -r`, `rm -rf`, `rm -rf /`, `rm -rf *`는 혼자 실행하지 않는다.

## 오늘의 생존 명령 10개

| 명령 | 한 줄 의미 |
|---|---|
| `pwd` | 현재 폴더를 본다 |
| `ls` | 파일과 폴더를 본다 |
| `cd` | 폴더를 이동한다 |
| `cat` | 파일 전체를 출력한다 |
| `head` | 파일 앞부분을 본다 |
| `tail` | 파일 뒷부분을 본다 |
| `grep` | 특정 단어가 있는 줄을 찾는다 |
| `find` | 조건에 맞는 파일을 찾는다 |
| `--help` | 명령 사용법을 본다 |
| `echo $?` | 직전 명령의 성공/실패 상태를 본다 |

## 터미널 복구 순서

1. 현재 위치: `pwd`
2. 주변 파일: `ls`
3. 대상 파일 존재 여부: `ls <폴더>` 또는 `find`
4. 명령 도움말: `<명령> --help`
5. 에러 핵심 단어 확인
6. 로그 확인: `tail`, `grep`
7. 질문 작성: 하려던 일, 보인 증상, 해본 것, 궁금한 것

복구할 때 삭제부터 하지 않는다. `rm -rf` 같은 명령은 원인 확인 도구가 아니라 삭제 도구다.

## Live QA

남은 시간은 Day3 실습에서 막힌 부분을 해결한다.

우선순위:

1. 현재 폴더와 경로 문제
2. `No such file or directory`, `command not found` 해석
3. `grep`, `find`, `tail` 명령 사용
4. 깨진 명령 8개 중 이해되지 않은 문제
5. incident note 작성
6. 삭제 명령 안전 규칙

질문할 때는 실제 에러 메시지와 `pwd` 결과를 함께 가져온다.

## Day4로 이어지는 연결

Day4에서는 “파일이 어디 있나”를 넘어 “요청이 어느 구성요소를 지나가나”를 본다. 오늘 배운 터미널 기본기는 내일도 그대로 사용한다.
