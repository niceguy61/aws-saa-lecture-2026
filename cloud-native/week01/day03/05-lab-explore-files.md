# 5교시 - 핸즈온: 탐색과 파일 확인 연습

## 목표

이 시간의 목표는 `playground` 폴더에서 필요한 파일을 직접 찾고, 설정과 로그의 관계를 설명하는 것이다. 난이도는 오전보다 올라간다. 모든 명령을 한 번에 이해하지 못해도, 증거를 모아 답을 좁히면 된다.

이 세션의 끝에서 우리는 다음을 할 수 있어야 한다.

- 파일 구조를 보고 서비스 구성요소를 추론한다.
- `cat`, `head`, `tail`, `grep`, `find`로 필요한 내용을 찾는다.
- 설정 파일과 에러 로그의 연결을 설명한다.

## 준비

저장소 루트에서 시작한다.

```bash
cd cloud-native/week01/day03/playground
```

현재 위치와 파일 구조를 확인한다.

```bash
pwd
ls
find . -maxdepth 3 -type f
```

`find`가 어렵다면 아래 명령을 나누어 실행한다.

```bash
ls apps
ls apps/api
ls apps/web
ls config
ls logs
```

## 미션 1 - 서비스 이름 찾기

아래 질문에 답한다.

1. API 서비스 이름은 무엇인가?
2. Web 서비스 이름은 무엇인가?
3. 두 서비스가 사용하는 포트는 각각 무엇인가?

힌트:

```bash
cat apps/api/service.txt
cat apps/web/service.txt
cat config/app.env
```

정리 표:

| 항목 | 값 | 근거 파일 |
|---|---|---|
| API 이름 | | |
| Web 이름 | | |
| API 포트 | | |
| Web 포트 | | |

파일 안의 `service=orders-api`처럼 생긴 줄은 `키=값` 형태로 읽는다. 왼쪽은 이름표, 오른쪽은 실제 값이다. 예를 들어 `API_PORT=8000`은 API가 8000번 포트를 쓴다는 뜻으로 읽는다.

## 미션 2 - 실패한 요청 찾기

`logs/access.log`에서 실패한 요청을 찾는다.

```bash
grep "status=500" logs/access.log
```

```bash
grep "status=404" logs/access.log
```

질문:

1. 어떤 경로에서 `500`이 발생했는가?
2. 어떤 경로에서 `404`가 발생했는가?
3. `500`과 `404`는 같은 종류의 실패인가?

힌트:

- `path=/api/orders`는 요청한 주소의 경로를 뜻한다.
- `status=500`은 서버 내부 처리 실패를 뜻한다.
- `status=404`는 요청한 경로를 찾지 못했다는 뜻이다.

정리:

| 상태 코드 | 경로 | 의미 추정 |
|---|---|---|
| 500 | | |
| 404 | | |

## 미션 3 - 설정 누락 찾기

에러 로그에서 설정 관련 에러를 찾는다.

```bash
grep "missing" logs/error.log
```

설정 파일을 본다.

```bash
cat config/app.env
```

질문:

1. 에러 로그에서 빠졌다고 말하는 설정 이름은 무엇인가?
2. `config/app.env`에는 그 설정이 있는가?
3. 이 문제는 코드 문제에 가까운가, 설정 문제에 가까운가?

주의할 점:

- 설정 파일에 `#`으로 시작하는 줄은 보통 설명 주석이다.
- `# DATABASE_URL ...`처럼 주석에 단어가 있어도 실제 설정값이 들어간 것은 아니다.
- 실제 설정값은 보통 `DATABASE_URL=...`처럼 `#` 없이 시작한다.

## 미션 4 - 증거 3개와 결론 1개

팀별로 아래 형식으로 정리한다.

```text
증거 1:
증거 2:
증거 3:
결론:
다음 확인:
```

예시:

```text
증거 1: logs/access.log에서 /api/orders status=500 확인
증거 2: logs/error.log에서 DATABASE_URL missing 확인
증거 3: config/app.env에 DATABASE_URL 값이 없음
결론: 주문 API 실패는 데이터베이스 연결 설정 누락 가능성이 높음
다음 확인: DATABASE_URL을 어디서 주입해야 하는지 확인
```

## 도전 과제

빠르게 끝난 팀은 아래를 수행한다.

```bash
grep "duration_ms" logs/access.log
```

가장 느린 요청 경로를 찾는다. 정확한 계산보다 “어떤 요청이 느린 편인지”를 찾는 데 집중한다.
