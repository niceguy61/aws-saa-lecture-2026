# 1교시 - 터미널 자신감 워밍업

## 목표

이 시간의 목표는 터미널을 “무서운 검은 화면”이 아니라 상태를 확인하고 요청을 보내는 도구로 보는 것이다. Docker와 Kubernetes를 배우면 대부분의 조작은 터미널 명령으로 시작된다.

이 세션의 끝에서 우리는 다음을 할 수 있어야 한다.

- 명령, 옵션, 인자, 출력, 에러를 구분한다.
- 명령을 실행하기 전에 “무엇을 확인하려는지” 말한다.
- 실패한 명령을 보고 당황하지 않고 첫 단서를 찾는다.

## 오늘 한 줄 요약

터미널은 외우는 곳이 아니라, 시스템에게 질문하고 답을 읽는 곳이다.

## 시작 질문

> 터미널에서 가장 무서운 것은 무엇인가요?

자주 나오는 답:

- 영어 에러가 길게 나온다.
- 어디에 있는지 모르겠다.
- 잘못 입력하면 컴퓨터가 망가질 것 같다.
- 뭘 복사해야 하는지 모르겠다.

이 불안은 자연스럽다. 그래서 오늘은 “빠르게 치기”보다 “천천히 읽기”를 훈련한다.

## 명령의 구조

명령은 보통 아래 모양이다.

```text
명령 옵션 인자
```

예시:

```bash
ls -la cloud-native/week01/day03
```

| 부분 | 예시 | 뜻 |
|---|---|---|
| 명령 | `ls` | 무엇을 할지 정한다 |
| 옵션 | `-la` | 어떻게 할지 조건을 붙인다 |
| 인자 | `cloud-native/week01/day03` | 어디에 대해 할지 대상을 준다 |

모든 명령이 이 모양을 완벽히 따르는 것은 아니다. 하지만 처음에는 “무엇을, 어떻게, 어디에”라고 나누어 읽으면 대부분의 명령이 덜 무섭다.

## 읽기 명령과 변경 명령

처음에는 읽기 명령을 많이 쓴다. 읽기 명령은 대체로 상태를 확인할 뿐 파일이나 시스템을 바꾸지 않는다.

| 종류 | 예시 | 위험도 |
|---|---|---|
| 읽기 | `pwd`, `ls`, `cat`, `head`, `tail`, `grep` | 낮음 |
| 생성/수정 | `mkdir`, `touch`, 편집기 저장 | 중간 |
| 삭제/초기화 | `rm`, `git reset`, `docker system prune` | 높음 |
| 권한/비용 영향 | `chmod`, cloud 생성/삭제 명령 | 높음 |

수업에서는 삭제나 초기화 명령을 복사하기 전에 반드시 의미를 확인한다.

## 특히 조심할 삭제 명령

`rm`은 파일이나 폴더를 삭제하는 명령이다. 휴지통으로 보내는 것이 아니라 바로 지우는 방식으로 동작하는 경우가 많다. 그래서 초반 실습에서는 `rm`을 거의 쓰지 않는다.

| 명령 | 뜻 | 위험 |
|---|---|---|
| `rm file.txt` | 파일 하나 삭제 | 되돌리기 어려울 수 있음 |
| `rm -r folder` | 폴더와 안의 파일을 함께 삭제 | 폴더 전체가 사라짐 |
| `rm -rf folder` | 묻지 않고 강제로 폴더 삭제 | 오타가 나면 큰 피해 |
| `rm -rf /` | 시스템 최상위부터 삭제 시도 | 절대 실행 금지 |
| `rm -rf *` | 현재 폴더의 모든 항목 삭제 | 현재 위치를 착각하면 위험 |

`-r`은 폴더 안으로 계속 들어가며 지운다는 뜻이고, `-f`는 확인 질문을 줄이고 강제로 진행한다는 뜻에 가깝다. 둘이 합쳐진 `rm -rf`는 매우 강한 삭제 명령이다.

삭제 명령을 보기 전에는 아래를 먼저 확인한다.

```bash
pwd
ls
```

수업 규칙:

- `rm`, `rm -r`, `rm -rf`는 혼자 실행하지 않는다.
- `/`, `*`, `~`, `..`가 삭제 명령과 함께 보이면 멈춘다.
- AI가 삭제 명령을 제안하면 바로 실행하지 말고, 지우려는 대상이 정확히 무엇인지 먼저 확인한다.
- 실습에서 정리(cleanup)가 필요하면 자료에 있는 정리 명령만 사용한다.

## 복사해서 실행할 때의 규칙

수업 자료의 코드 블록은 보통 터미널에 입력할 명령이다.

```bash
pwd
```

자료나 블로그에서 아래처럼 보이는 경우도 있다.

```text
$ pwd
```

이때 `$`는 “여기부터 입력하세요”라는 표시인 경우가 많다. 실제로는 `pwd`만 입력한다. `#`, `>` 같은 기호도 문맥에 따라 프롬프트 표시일 수 있으니, 헷갈리면 그대로 복사하기 전에 질문한다.

## 실습 - 첫 질문 5개

터미널에서 하나씩 실행한다.

```bash
pwd
```

```bash
whoami
```

```bash
date
```

```bash
echo hello-terminal
```

```bash
ls
```

화면을 깨끗하게 비우고 싶을 때는 아래 명령을 쓸 수 있다.

```bash
clear
```

관찰할 것:

- `pwd`는 현재 폴더를 보여준다.
- `whoami`는 현재 사용자 이름을 보여준다.
- `date`는 현재 시간을 보여준다.
- `echo`는 입력한 문장을 다시 출력한다.
- `ls`는 현재 폴더의 파일과 폴더를 보여준다.
- `clear`는 화면을 지울 뿐 파일을 삭제하지 않는다.

## 에러를 질문으로 바꾸기

예를 들어 아래처럼 입력했다고 생각한다.

```bash
lss
```

가능한 출력:

```text
command not found: lss
```

이 메시지는 “컴퓨터가 망했다”가 아니다. “`lss`라는 명령을 찾지 못했다”는 뜻이다. 좋은 질문은 이렇게 바뀐다.

```text
제가 하려던 일: 현재 폴더 파일 목록 보기
보인 증상: lss command not found
이미 해본 것: 아직 없음
궁금한 것: 파일 목록을 보는 올바른 명령이 무엇인지 알고 싶음
```

## 오늘의 기준

오늘부터 명령을 볼 때는 세 가지를 먼저 말한다.

1. 이 명령은 무엇을 확인하는가?
2. 이 명령은 파일이나 시스템을 바꾸는가?
3. 성공하면 어떤 출력이 나와야 하는가?
