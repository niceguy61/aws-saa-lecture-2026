# 8교시 - Day1 핵심 정리와 Live QA

## 목표

이 시간의 목표는 첫날에 본 과정 흐름, 학습 규칙, 개발 도구 준비 상태를 다시 묶고, 남은 설치/계정/도구 질문을 Live QA로 해결하는 것이다.

이 세션의 끝에서 우리는 다음을 할 수 있어야 한다.

- 6주 과정이 왜 Docker, Kubernetes, AWS, Observability, AI로 이어지는지 말한다.
- VS Code, 터미널, Git, Docker Desktop, WSL의 역할을 구분한다.
- AI와 coding agent를 사용할 때 무엇을 확인해야 하는지 설명한다.
- 내일 실습 전에 해결해야 할 준비 항목을 적는다.

## 반드시 알아야 할 키포인트

- Cloud Native는 도구 이름 암기가 아니라 앱을 안정적으로 운영하는 방식이다.
- Docker는 실행 환경 차이를 줄이기 위해 등장했다.
- Kubernetes는 많은 컨테이너를 원하는 상태로 운영하기 위해 등장했다.
- 터미널은 명령을 실행하고 결과를 관찰하는 기본 도구다.
- AI가 만든 답은 실제 파일, 명령 출력, 테스트 결과로 확인해야 한다.
- password, token, API key, private key는 AI 도구나 공개 문서에 붙여넣지 않는다.

## Live QA

남은 시간은 질문 해결에 사용한다.

우선순위:

1. 내일 실습을 막는 설치 문제
2. Docker Desktop, WSL, Git, 터미널 관련 오류
3. 계정 로그인과 권한 문제
4. AI 사용 규칙과 secret 취급 질문
5. 6주 과정 흐름에 대한 이해 질문

질문할 때는 아래 형식을 사용한다.

```text

보인 증상:
이미 해본 것:
궁금한 것:
```

## 2일차 전에 준비할 것

Day2에는 Python으로 만든 아주 작은 웹앱을 실행한다. 웹 개발자가 되기 위한 실습이 아니라, Cloud Native에서 계속 등장하는 실행 단위를 직접 보기 위한 실습이다.

확인할 것:

| 항목 | 확인 방법 | 막혔을 때 |
|---|---|---|
| Python | `python --version` 또는 `python3 --version` | Day2 첫 시간 설치 안내를 따라간다 |
| 현재 폴더 확인 | `pwd` 또는 터미널의 경로 표시 | 폴더 이동을 먼저 연습한다 |
| 브라우저 | Chrome 또는 Edge 실행 | localhost 접속 실습에 사용한다 |
| 터미널 복사/붙여넣기 | 짧은 명령 1개 실행 | 명령과 출력을 구분해서 기록한다 |

Python이 아직 없어도 괜찮다. 내일 첫 시간에 설치와 확인을 먼저 진행한다.
