# Cloud Native Course Production

Use this skill to produce classroom-ready Cloud Native DevOps materials.

## Workflow

1. Start from the learner outcome.
2. Write a concrete production scenario.
3. Define the core mental model.
4. Add decision rules, tradeoffs, and common traps.
5. Create the lab with prerequisites, commands, expected output, verification, troubleshooting, and cleanup.
6. Add instructor notes with timing, demo flow, and expected learner mistakes.
7. Add quiz or debrief prompts with answer keys.
8. Add Mermaid diagrams or a stickman visual brief.

## Course Domains

- Docker and container foundations
- Kubernetes core architecture and workloads
- Kubernetes networking
- Cloud native security
- AWS cloud native computing
- Observability and operations

## Quality Bar

- Prefer official project documentation for factual claims.
- Keep commands reproducible and ordered.
- State OS, tool, cluster, and cloud assumptions.
- Avoid production credentials and unmanaged cloud spend.
- Include cleanup for every created resource.
- Connect every topic to deployment, scaling, networking, security, operations, reliability, or cost.
- Keep AWS material cloud-native and practical, centered on deployment and operations scenarios.
- From week 2 onward, raise depth to university STEM / junior engineer level, expand hands-on labs, verify lab commands, include technology evolution or industry trend context, and embed infographic-style architecture PNGs in addition to stickman images. Do not treat plain box-and-arrow SVG-style diagrams exported as PNG as finished visuals.
- For student-facing images, write titles and essential explanatory labels in Korean. Use English only for product names, commands, ports, protocols, and other technical identifiers.
